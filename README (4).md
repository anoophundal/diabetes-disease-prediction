# Diabetes Disease Prediction

A supervised machine learning pipeline that predicts diabetes risk from routine clinical
measurements, using the Pima Indians Diabetes dataset.

## Overview

This project compares three classification algorithms (Logistic Regression, Random
Forest, SVM) on 768 patient records, tunes the strongest candidate, and packages it into
a reusable inference function that scores a new patient from raw clinical inputs.

**Key result:** Random Forest (tuned) achieves **ROC-AUC 0.822** and **F1 0.661** on a
held-out test set, with Glucose and BMI identified as the strongest predictors —
consistent with established clinical risk factors for Type 2 diabetes.

## Dataset

[Pima Indians Diabetes Database](https://raw.githubusercontent.com/jbrownlee/Datasets/master/pima-indians-diabetes.data.csv)
— 768 female patients of Pima Indian heritage, 8 features + binary outcome.

| Feature | Description |
|---|---|
| Pregnancies | Number of times pregnant |
| Glucose | Plasma glucose concentration (2-hr oral glucose tolerance test) |
| BloodPressure | Diastolic blood pressure (mm Hg) |
| SkinThickness | Triceps skinfold thickness (mm) |
| Insulin | 2-hour serum insulin (mu U/ml) |
| BMI | Body mass index |
| DiabetesPedigreeFunction | Diabetes likelihood based on family history |
| Age | Age in years |
| **Outcome** | 1 = diabetic, 0 = non-diabetic (target) |

Roughly 35% of patients are positive for diabetes — moderately imbalanced, which is why
the pipeline reports F1 and ROC-AUC alongside accuracy rather than accuracy alone.

## Methodology

1. **Missing-value handling** — `Glucose`, `BloodPressure`, `SkinThickness`, `Insulin`,
   and `BMI` cannot be physiologically zero; zeros in these columns (up to 48.7% for
   Insulin) are treated as missing and median-imputed.
2. **Stratified train/test split** (80/20), preserving class balance in both sets.
3. **Preprocessing fit on training data only** (imputer + `StandardScaler`) to avoid
   test-set leakage.
4. **Model comparison** via 5-fold stratified cross-validation on the training set:
   Logistic Regression, Random Forest, SVM (RBF kernel), all with `class_weight="balanced"`.
5. **Hyperparameter tuning** of Random Forest with `GridSearchCV`, optimizing ROC-AUC.
6. **Final evaluation** on the untouched test set — classification report, confusion
   matrix, ROC curve, precision-recall curve.
7. **Feature importance** ranking from the tuned Random Forest.
8. **Model persistence** — imputer, scaler, and model bundled into
   `diabetes_model.joblib` for reuse outside the notebook.

## Results

### Cross-validated comparison (train set, 5-fold)

| Model | Accuracy | F1 | ROC-AUC |
|---|---|---|---|
| Logistic Regression | 0.762 ± 0.011 | 0.672 ± 0.013 | 0.844 ± 0.016 |
| Random Forest | 0.765 ± 0.028 | 0.633 ± 0.035 | 0.821 ± 0.025 |
| SVM (RBF) | 0.762 ± 0.033 | 0.693 ± 0.026 | 0.837 ± 0.030 |

### Tuned Random Forest — held-out test set

| Metric | Score |
|---|---|
| Accuracy | 0.740 |
| F1 | 0.661 |
| ROC-AUC | 0.822 |

### Top features by importance

1. Glucose (39.3%)
2. BMI (17.0%)
3. Insulin (11.8%)
4. Age (10.7%)

## Usage

```bash
pip install pandas numpy scikit-learn matplotlib seaborn joblib
jupyter notebook Diabetes_Prediction_Enhanced.ipynb
```

Run all cells to reproduce the analysis and regenerate `diabetes_model.joblib`. To score
a new patient once the model is trained:

```python
from predict import predict_diabetes  # or run the function cell in the notebook

patient = {
    "Pregnancies": 3, "Glucose": 158, "BloodPressure": 76, "SkinThickness": 36,
    "Insulin": 245, "BMI": 41.6, "DiabetesPedigreeFunction": 0.851, "Age": 44,
}
predict_diabetes(patient)
# {'prediction': 'Diabetes', 'probability': 0.842}
```

## Limitations

- Dataset is limited to female patients of Pima Indian heritage aged 21+; results may
  not generalize to other populations.
- 768 records is small by modern ML standards — cross-validation mitigates but doesn't
  eliminate variance in the reported metrics.
- This is a demonstration/portfolio project, not a validated clinical tool.

## Possible extensions

- SMOTE or other resampling to address class imbalance more directly
- SHAP values for per-prediction explanations
- A Streamlit or Flask demo wrapping `predict_diabetes()`
